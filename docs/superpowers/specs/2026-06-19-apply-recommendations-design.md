# Apply Recommendations to Cluster — Design

Date: 2026-06-19
Components:
- `scripts/python/fetch-cluster-usage.py` (new manifest renderer)
- `scripts/python/apply-recommendations.py` (new standalone applier)

## Goal

Close the loop on the existing resource-recommendations export. Today the tool
emits per-workload recommended `cpu/mem request/limit` values
(`recommendations.csv`) plus a per-namespace quota gate
(`recommendations-namespaces.csv`, `quota_action = INCREASE_QUOTA` when the
summed recommendations exceed the namespace ResourceQuota). This feature turns
those recommendations into something that actually changes the cluster:

1. A declarative, reviewable **YAML manifest** describing the resource changes.
2. An **applier** that does a **server-side dry-run by default** and only
   mutates the cluster when explicitly asked (`--execute`).

## Locked decisions

- **Scope = workload resources only.** The apply step patches container
  `requests`/`limits` on the workloads (Deployments / StatefulSets, per the
  kinds the rollup already classifies). It does **not** edit ResourceQuotas.
- **Manifest form = single multi-doc patch YAML.** One self-describing patch
  document per hot workload, applied via `kubectl patch --type=strategic`. Not
  a `kubectl apply` of full objects (would require whole specs) and not
  imperative `kubectl set resources`.
- **Quota guard = skip + warn.** Namespaces flagged `INCREASE_QUOTA` are
  omitted from the manifest entirely. A header comment lists each skipped
  namespace and the quota bump needed. The user raises quota manually, then
  re-runs the export.
- **Execute UX = dry-run default, `--execute` to apply.** Running the applier
  with no flag performs a server-side dry-run only (validates + shows old→new,
  changes nothing). Real changes require the explicit `--execute` flag.
- **Population = same as `recommendations.csv`.** Only workloads that qualify
  (hot on at least one resource) appear. Only the dimensions that qualified are
  changed; the paired non-hot dimension is carried at its current value so a
  strategic-merge does not drop it.

## Architecture

### 1. Manifest renderer (in `fetch-cluster-usage.py`)

`fetch-cluster-usage.py` is **stdlib-only** by design (it runs in-cluster as a
CronJob), so the renderer hand-emits the YAML — it does **not** import PyYAML.
The output is a controlled structure (k8s names, quantity strings) emitted with
explicit double-quoting of string scalars so it round-trips through any YAML
parser. New renderer following the existing `render_*` convention:

```python
def render_recommendations_apply_yaml(trees, stream, target_util=80.0):
    """Emit one ResourcePatch YAML document per hot workload, skipping
    namespaces flagged INCREASE_QUOTA (listed in a header comment)."""
```

Wired into `write_report_files(...)` next to the existing five recommendation
files, gated on the same `recommendations_enabled` / `target_util` threading.
Because `write_all_reports(...)` already calls `write_report_files` for the
main dir and each `by-stage/<stage>/` folder, the manifest appears in all of
them automatically. Output filename: `recommendations-apply.yaml`.

The renderer reuses the existing pure layer:
- `compute_recommendation(container_totals, target_util)` run **per container
  name** (via a new `workload_container_recommendations` helper) for the
  recommended values.
- `namespace_recommendation_summary(ns_node, target_util)` for the
  `quota_action` used by the skip-flagged guard.

It does **not** introduce a new value formula. Numbers are formatted as valid
Kubernetes quantity strings by **new** dedicated helpers `cpu_quantity` /
`mem_quantity` (e.g. `320m`, `256Mi`). The existing `fmt_cores` / `fmt_bytes`
are **not** reused here: `fmt_cores` appends a `c` (cores) / `µ` suffix that is
not a valid Kubernetes quantity, so it would not round-trip through kubectl.

#### Manifest document shape

Header (once, at top of file):

```yaml
# recommendations-apply.yaml — generated by fetch-cluster-usage.py
# target_util=80
# SKIPPED (namespace quota must be raised first — quota_action=INCREASE_QUOTA):
#   pid-123-app-prod-01: cpu_limit sum 4200m > quota 4000m; mem_limit ...
#   pid-456-...: ...
```

One document per included hot workload:

```yaml
---
# pid-123-app-dev-01 / Deployment web
#   cpu: req 250m→250m, lim 250m→320m | mem: req 200Mi→200Mi, lim 200Mi→256Mi
apiVersion: forensic-dashboards/v1
kind: ResourcePatch
target:
  kind: Deployment
  namespace: pid-123-app-dev-01
  name: web
patch:                       # strategic-merge body, applied verbatim
  spec:
    template:
      spec:
        containers:
          - name: web
            resources:
              requests: {cpu: "250m", memory: "200Mi"}
              limits:   {cpu: "320m", memory: "256Mi"}
```

The old→new summary lives in the per-document header comment (above
`apiVersion`); there is no separate `current` block in the document body — the
manifest stays lean and the applier only ever reads `target` and `patch`.

Notes:
- `target.kind` / `name` / `namespace` come from the workload node
  (`wl["kind"]`, `wl["name"]`, namespace from the tree).
- The patch `containers` list is keyed by container `name` (strategic-merge
  patchMergeKey), so multi-container workloads get one list entry per container
  that has a recommendation.
- Within a container's `resources`, only the qualifying dimensions are
  emitted, and for each the patch sets **both** `requests` and `limits`
  (`compute_recommendation` always produces the pair together for a hot
  resource). Cold dimensions are left out entirely — a strategic-merge patch
  merges the `requests`/`limits` maps by key, so untouched keys (e.g. a cold
  `memory` limit) are preserved on the live object. This keeps each document
  minimal.

#### Quota guard (skip + warn)

For each namespace, compute `namespace_recommendation_summary`. If
`quota_action == "INCREASE_QUOTA"`, **emit no documents** for that namespace and
add a line to the header `SKIPPED` block naming the namespace and which
dimensions exceed (`*_status == "EXCEEDS"`) with their sum vs quota.

### 2. Applier — `scripts/python/apply-recommendations.py`

Standalone script. Parses the multi-doc YAML, iterates the `ResourcePatch`
documents, shells out to `kubectl` (or `oc`).

CLI:
- `--manifest PATH` (required) — path to `recommendations-apply.yaml`.
- `--execute` — perform real changes. Absent ⇒ dry-run only.
- `--context NAME` — kube context (passed as `--context`).
- `--oc` — use the `oc` binary instead of `kubectl`.
- `--kubectl PATH` — override the kubectl binary path (default `kubectl`).

Per document, build argv:

```
<bin> [--context NAME] patch <target.kind> <target.name>
    -n <target.namespace>
    --type=strategic
    --patch <json-or-yaml of patch>
    [--dry-run=server]        # present unless --execute
```

- The `patch` body is serialized (JSON is valid YAML and avoids quoting
  surprises) and passed via `--patch`.
- **Dry-run (default):** `--dry-run=server` is included. The API server
  validates against the live object (schema, admission, quota). Print, per
  workload, the `old→new` summary (from the doc's header comment) and the
  kubectl result line.
- **Execute (`--execute`):** same call without `--dry-run`. Print
  applied/failed per workload and a final summary. Exit non-zero if any patch
  failed.
- **Missing workload:** if kubectl reports NotFound, mark the workload
  `skipped (not found)` and continue; not fatal.
- **Flagged-namespace warning:** the applier re-prints the header `SKIPPED`
  block so the quota caveat is visible at apply time, not just at generation
  time.

The applier shells out (subprocess) to kubectl/oc rather than using a
Kubernetes client library, matching the repo's existing kubectl/oc-driven
scripts. It is a locally-run dev tool (not the in-cluster CronJob), so it may
use **PyYAML** (`yaml.safe_load_all`) to parse the manifest; it fails with a
clear message if PyYAML is absent. The patch body is re-serialized to JSON
(stdlib `json`) for the `--patch` argument (JSON is valid input to
`kubectl patch` and avoids shell-quoting pitfalls).

## Output files

- `recommendations-apply.yaml` — added to the output dir and every
  `by-stage/<stage>/` folder, alongside the existing recommendation files.

## Edge cases

- **No hot workloads / all peaks missing:** the manifest has only the header
  and no documents. The applier reports "nothing to apply" and exits 0.
- **All in-scope namespaces flagged INCREASE_QUOTA:** all documents skipped;
  manifest is header-only with a populated SKIPPED block; applier prints the
  warning and exits 0 (nothing to do).
- **Per-container recommendations:** `compute_recommendation` runs per
  container *name* (peak taken as the max across the workload's replicas, limit
  from the template), since a strategic-merge patch addresses containers by
  name. The CSV's workload-aggregate recommendation is not reused for the
  manifest. Idle workloads (no running pods → no per-container peak) never
  qualify and produce no document.
- **Multi-container workload, only one container hot:** one list entry for the
  hot container; cold containers are not listed (untouched).
- **Workload deleted between export and apply:** kubectl NotFound ⇒ skipped,
  not fatal.
- **Container renamed between export and apply:** strategic-merge would add a
  new container entry; the server-side dry-run surfaces the resulting spec so
  the discrepancy is caught before `--execute`.

## Testing

Renderer (in `scripts/python/tests/`):
- One `ResourcePatch` document per hot workload; population matches
  `recommendations.csv`.
- Flagged (`INCREASE_QUOTA`) namespace: no documents emitted; SKIPPED header
  line present with the exceeding dimension(s).
- Paired non-hot dimension carried at its current value (merge safety).
- Multi-container: only hot containers listed, keyed by name.
- Empty / no-hot input ⇒ header only, zero documents.
- Emitted quantity strings are valid Kubernetes quantities
  (`cpu_quantity` / `mem_quantity` output) and round-trip via `parse_cpu` /
  `parse_mem`.
- The emitted manifest round-trips through `yaml.safe_load_all` (well-formed
  multi-doc YAML), asserted in the renderer test using PyYAML as a test-only
  dependency.

Applier:
- Correct kubectl argv for dry-run (includes `--dry-run=server`) vs execute
  (omits it), with `--oc` / `--context` / `--kubectl` variants (kubectl mocked,
  argv asserted).
- NotFound ⇒ workload skipped, run continues.
- Any failed patch under `--execute` ⇒ non-zero exit.
- Flagged-namespace SKIPPED block is re-printed.
- Header-only manifest ⇒ "nothing to apply", exit 0.

## Out of scope

- ResourceQuota edits (quota increases stay manual — surfaced by the existing
  `recommendations-namespaces.csv` and the SKIPPED block).
- Rollback / revert of applied changes.
- Workload kinds beyond those the existing rollup classifies.
- A Kubernetes client-library integration (the applier shells out to
  kubectl/oc).
